A continuación se presentan los diagramas correspondientes al caso de uso UC-034 – Obtener Ubicación, modelados según el Proceso Unificado de Desarrollo de Software (Jacobson, Booch, Rumbaugh). Dado que este caso de uso no involucra interacción directa con un usuario, sino que es un proceso interno del sistema, los diagramas se centran en la lógica de control, los servicios externos y las entidades.

1. Diagrama de Actividad
Muestra el flujo del sistema al intentar obtener la ubicación, considerando los servicios GPS y de red celular, la consulta de batería y los caminos de fallback.

plantuml
@startuml
|Sistema|
start
:Inicia obtención de ubicación
(desde estado de alarma);

:Invoca Servicio GPS
con timeout de 10 segundos;

:Obtiene nivel de batería
(ejecuta UC-038);

if (¿Nivel de batería crítico?) then (sí)
  :Cancela solicitud GPS;
  :Invoca Servicio Red Celular
  con timeout de 10 segundos;
  |Servicio Red Celular|
  if (¿Ubicación recibida?) then (sí)
    :Devuelve coordenadas y precisión;
    |Sistema|
    :Marca método como "Red";
  else (no)
    |Sistema|
    :Recupera última ubicación almacenada;
    :Marca método como "Almacenada";
  endif
else (no)
  |Servicio GPS|
  if (¿Ubicación recibida dentro del timeout?) then (sí)
    :Devuelve ubicación con precisión aceptable;
    |Sistema|
    :Marca método como "GPS";
  else (no)
    |Sistema|
    :Cancela/timeout GPS;
    :Invoca Servicio Red Celular
    con timeout de 10 segundos;
    |Servicio Red Celular|
    if (¿Ubicación recibida?) then (sí)
      :Devuelve coordenadas y precisión;
      |Sistema|
      :Marca método como "Red";
    else (no)
      |Sistema|
      :Recupera última ubicación almacenada;
      :Marca método como "Almacenada";
    endif
  endif
endif

|Sistema|
:Guarda ubicación (timestamp, método, coordenadas)
(ejecuta UC-037);

:Retorna ubicación con metadatos;
stop
@enduml
Bosquejo:
El diagrama utiliza carriles para el Sistema, Servicio GPS y Servicio Red Celular. El flujo principal comienza con la solicitud a GPS y la consulta paralela de batería. Si la batería es crítica, se descarta el GPS y se intenta directamente la red celular; en caso contrario, se espera la respuesta del GPS. Si cualquiera de los dos servicios falla (timeout o baja precisión), se recurre a la última ubicación almacenada. Finalmente se guarda la ubicación mediante UC-037 y se retorna.

4. Diagrama de Colaboración
Ilustra el intercambio de mensajes entre los objetos durante el flujo exitoso por GPS y el camino alternativo de red celular.

plantuml
@startuml
control "ControladorObtenerUbicacion" as ctrl
actor "Servicio GPS" as gps
actor "Servicio Red Celular" as red
control "ControladorBateria" as bat
control "ControladorAlmacenamiento" as alm
entity "Ubicacion" as u

ctrl -> gps : 1. solicitarUbicacion(timeout=10s)
ctrl -> bat : 2. obtenerNivelBateria()
bat --> ctrl : 3. nivel

alt GPS exitoso y batería no crítica
  gps --> ctrl : 4. ubicacion(precision)
  ctrl -> alm : 5. guardarUbicacion(ubic, "GPS")
else fallo GPS o batería crítica
  ctrl -> gps : 4a. cancelar()
  ctrl -> red : 5a. solicitarUbicacion(timeout=10s)
  red --> ctrl : 6a. ubicacion(precision)
  ctrl -> alm : 7a. guardarUbicacion(ubic, "Red")
else red también falla
  red --> ctrl : 6b. error/timeout
  ctrl -> alm : 7b. recuperarUltimaUbicacion()
  alm --> ctrl : 8b. ultimaUbicacion
  ctrl -> alm : 9b. guardarUbicacion(ultimaUbicacion, "Almacenada")
end

alm -> u : crear/actualizar
ctrl --> ctrl : retornar ubicación con metadatos
@enduml
Bosquejo:
Se muestra la secuencia de colaboración:

El controlador solicita la ubicación al GPS y el nivel de batería en paralelo.

Si el GPS es exitoso y la batería no es crítica, se guarda con método "GPS".

Si hay fallo del GPS o la batería es crítica, se cancela el GPS y se intenta la red celular. Si la red responde, se guarda como "Red".

Si ambos servicios fallan, se recupera la última ubicación almacenada y se marca como "Almacenada".

Finalmente, el controlador de almacenamiento persiste la ubicación y el controlador principal devuelve el resultado.

Fallo también de la red → se recupera la última ubicación almacenada y se marca como "Almacenada".

En todos los casos se persiste la ubicación y se retorna al proceso invocante.

1. Diagrama de Actividad
Representa el flujo automatizado de la grabación de audio, incluyendo la evaluación del nivel de batería, la adaptación de calidad y la segmentación continua.

plantuml
@startuml
|Sistema|
start
:La alarma se activa (UC-001);

:Inicia el servicio de grabación de audio
en segundo plano;

:Obtiene nivel de batería
(ejecuta UC-038);

if (¿Nivel de batería?) then (Normal)
  :Adopta formato de audio
  con calidad óptima;
elseif (Bajo)
  :Reduce calidad de audio a la mitad
  y comprime el formato;
else (Crítico)
  :Detiene la captura de audio;
  :Registra limitación por batería;
  stop
endif

repeat
  :Captura flujo de audio;
  :Divide en segmento de 15 segundos
  (duración configurable);
  :Asocia al segmento:
  - ID de la alarma
  - Timestamps de inicio y fin;
  :Guarda el segmento de audio
  (ejecuta UC-037);

  :Espera siguiente intervalo;
repeat while (¿Alarma activa? y ¿Batería no crítica?) is (sí)
-> no

stop
@enduml
Bosquejo:
El diagrama tiene un único carril del Sistema. Comienza con la activación de la alarma. Luego se consulta el nivel de batería (UC-038) y se toma una decisión: calidad normal, calidad reducida (batería baja) o detención total (batería crítica). Si la grabación continúa, entra en un bucle donde se captura el audio, se segmenta cada 15 segundos, se asigna metadatos (ID de alarma, timestamps) y se guarda mediante UC-037. El bucle termina cuando la alarma finaliza o la batería cae a nivel crítico.
